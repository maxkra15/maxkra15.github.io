RoboLearn · Isaac Lab · Locomotion benchmark

Sample efficiency and training speed for G1 locomotion

A controlled comparison of RSL PPO, Warp PPO, and the authors’ FlashSAC implementation on the same Isaac Lab task.

Maximilian Krause · 9 October 2026 · Three independent learner seeds · One isolated NVIDIA L40 per run · 50.38 million transitions per run
FindingsLearning curvesRuntimePolicy qualityVideoMethodsLimitsEvidence

Abstract

FlashSAC reached the measured walking criterion with fewer collected transitions and achieved lower final velocity error in this cohort. Warp PPO reduced PPO’s learning-phase cost by 18.6%, but rollout dominated runtime, limiting its training-loop gain to 2.5%. All nine final policies passed the forward-walking criterion. Preparation and evaluation costs make the complete command-pipeline comparison less favorable to Warp and FlashSAC than the training-loop numbers alone suggest.

2 of 3 seeds

FlashSAC passed at 12.29M transitions. Neither PPO had a passing seed at that checkpoint. This is evidence of better observed sample efficiency.

1.23× faster updates

Warp PPO: 125.5 seconds of learning versus RSL PPO’s 154.2 seconds. The complete production training loop was only 1.025× faster.

100% forward survival

All learners survived every final forward evaluation. Native-command survival was 87.5% for RSL, 99.5% for Warp, and 100% for FlashSAC.

01How much experience was needed?

At 24.58M transitions, all three FlashSAC seeds passed the walking gate, versus two seeds for each PPO. The first passing checkpoints were 500 / 500 / 1000 iterations for FlashSAC, 1000 / 1500 / 1000 for Warp PPO, and 1000 / 1000 / 2050 for RSL PPO. One RSL seed later failed at iteration 1500 before recovering.

02Where did the time go?

PPO spent approximately 82–85% of its training loop collecting rollouts. Accelerating its remaining learning phase therefore produced a small overall gain. FlashSAC performed more, smaller replay update calls and used larger networks; its higher full-budget runtime coexists with earlier measured learning success.

Three-seed means. The complete measured command pipeline took 18.29 / 18.51 / 32.43 minutes for RSL / Warp / FlashSAC. It excludes OSMO queueing, container bootstrap, and artifact retrieval. This is not a cache-cleared machine-start benchmark.

What “faster” means here. Warp’s production loop is faster; the measured command pipeline, including its mandatory preparation smoke and evaluations, is slightly slower than RSL’s. Flash compilation also enters its early production iterations. Flash’s rollout/update split uses CUDA-event attribution, whereas PPO phases use synchronized wall timing; these phase totals do not compare identical gradient work.

03What did the final policies achieve?

At the matched final budget, FlashSAC had the lowest mean planar velocity error in both evaluation scenarios. Every forward evaluation passed walking and survival. Native commands are broader: they include varying planar and yaw commands as well as standing, so native tracking success is a different metric from forward walking.

05Experimental setup

EnvironmentIsaac-Velocity-Flat-G1, Isaac Lab 3 on Newton MJWarp. Shared rewards, observations, commands, action scale, resets, terminations, and initial episode-counter randomization. All nine runs have the same recorded MDP hash.

Training budget and hardware1,024 parallel environments × 24 steps × 2,050 iterations = 50,380,800 collected transitions. Fresh policy and optimizer for seeds 0, 1, 2. Each run had one isolated L40, 15 CPUs, and 64 GiB RAM.

Common evaluation64 worlds, 20-second native episodes, deterministic policy actions, noise and pushes disabled. Evaluation seed = 10000 + learner seed. Checkpoints: 250, 500, 1000, 1500, 2050. Two scenarios produce 90 evaluations total.

Walking gateAt least 80% of worlds satisfy walking, mean planar error ≤ 0.2 m/s, and survival ≥ 90%. A walking world survives with planar error < 0.25 m/s, yaw-rate error < 0.4 rad/s, and forward speed > 0.25 m/s.

Measured software. Python 3.12.14; Torch 2.12.0+cu130 / CUDA 13.0; RSL-RL 5.5.1; Warp 1.17.0; Warp-NN 0.4.0; Newton 1.6.1; MuJoCo Warp 3.12.0. The measured RoboLearn distribution was 0.1.0 at the immutable revision listed below.

Algorithm settings and learning work

Matched PPO: ELU MLPs with widths 256/128/128, directly learned state-independent Gaussian standard deviation per action, unclipped policy actions, unnormalized observations, five epochs × four shuffled minibatches, γ = 0.99, λ = 0.95, initial adaptive learning rate 0.001 at target KL 0.01, entropy 0.008, full-MSE clipped value loss, and separate gradient norm limits of 1. Warp uses the tiled Linear backward path. Both have 167,243 parameters and 41,000 actor/critic Adam updates. A fixed-rollout diagnostic compared parameters and optimizer moments to Torch, with errors below 10⁻⁶.

FlashSAC: authors’ implementation with bounded tanh-Gaussian actions, 10M replay capacity, 100K-transition warmup, batch 2,048, three-step returns, two critic updates per vector step and one actor update per two critic updates, AMP, and Torch compilation. Actor width 128 and critic width 256, two blocks each; twin distributional critics with 101 atoms. The model has 2,532,746 parameters. Each run attempted 98,202 critic and 49,101 actor updates. Actual actor updates were 49,042 / 49,038 / 49,039, reflecting AMP skips; all critic updates completed.

Use the current integration or reproduce the frozen experiment

The commands below use the current integration and RoboLearn 0.2. Install the supported Isaac Lab environment first, then install RoboLearn without replacing simulator-owned dependencies. For the exact measured stack, use the pinned checkout and frozen lock in the G1 reproduction guide, which also contains the production overrides and common evaluation commands.

git clone --branch experiment/g1-learning-baselines https://github.com/maxkra15/IsaacLab.git
git clone https://github.com/maxkra15/RoboLearn.git
# From the configured Isaac Lab environment:
uv pip install --no-deps -e /path/to/RoboLearn
uv run --no-sync isaaclab train --rl_library robolearn \
    --algorithm warp_ppo --task Isaac-Velocity-Flat-G1 --num_envs 1024 \
    --max_iterations 2050 --seed 0 physics=newton_mjwarp \
    agent.algorithm_cfg.optimized_linear_backward=true

The registered Warp PPO recipe supplies the matched numerical settings; the explicit override selects the tested tiled gradients. Select --algorithm flashsac for the corrected Flash registration. Use the benchmark harness in the guide for matched timing and common evaluations.

06Interpretation and limits

  • A useful result, with a narrow scope. Three learner seeds on one flat G1 task support the observed sample-efficiency and runtime conclusions. They do not establish universal speed or quality advantages. Matching seed numbers does not match every implementation’s random draw.
  • Shared MDP, algorithm-specific work. Flash uses bounded actions, a larger model, distributional critics, replay, and AMP. PPO uses unclipped Gaussian actions and FP32 updates. Matching collected transitions does not match optimizer work or policy support.
  • Sampled success is not an exact convergence time. Evaluations were performed at five checkpoints after training. First-passing times are retrospective checkpoint production times; regressions and unseen behavior between checkpoints matter.
  • Integration benchmark, not a paper replication. The FlashSAC paper used Isaac Lab 2.1 with PhysX and a different PPO budget. This benchmark uses Isaac Lab 3/Newton, the authors’ code recipe, and an equal collected-transition budget. The paper’s separate real-robot experiment is also a different setup.
  • Current graphs leave rollout costs. A captured learner does not remove Torch MDP work or guarantee faster matrix operations. A fully captured Warp MDP and physics–learning graph would require a separate implementation and comparison.

07Evidence and reproducibility

All nine bundles passed SHA256 verification, checkpoint and optimizer audits, budget checks, and common-evaluation checks. Weights changed and remained finite. Native checkpoints are preserved; raw measurement JSON is unchanged. The three earlier Flash runs with different initial episode counters are retained as diagnostics and excluded here.

Measurements refer to the source revisions below. RoboLearn 0.2 preserves those learner kernels and math, and fixes the adapter’s unclipped-action storage with one device conversion/copy. That fix was made after these runs; no new timing measurement is claimed for it.
