2. Protocol and controls

Every call samples replay, updates the critic, updates actor and temperature every second call, applies parameter projections and target EMA, and returns the default 7/2 CPU scalar metrics. All rows use 1,024 synthetic environments, 123 observations, 37 actions and batch size 2,048. Each of five blocks has 20 warm calls and 200 measured calls; state continues across blocks. The measured budget per row is 1,000 critic, 500 actor and 500 temperature optimizer attempts. AMP skips remain explicit below.

All four benchmark processes use exactly the same canonical initial arrays and bit-identical transition fixtures, verified with per-array hashes. Each implementation reads back its loaded arrays exactly in the authors’ layout. Replay populations are checked against the pristine authors’ replay implementation. Fixtures contain no terminal or timeout transitions, so timeout-discount semantics are not validated. Common initialization does not imply identical random draws or optimizer trajectories.

Process order is old native pre, optimized first pass, old native post, optimized repeat. Old-native processes still construct the pristine official learner and ingest the shared fixture as an untimed reference, with zero author optimizer updates. Inside each optimized process, official Torch, the Torch port and native implementations run in that order. Compiler caches are retained across processes; this is not an independent cold-start comparison. No locked-clock crossover study or task-quality measurement is provided.

Native mixed precision uses FP16 dense operands with FP32 accumulation, outputs, activations, normalization, master weights and Adam. Torch AMP rounds more intermediate values to FP16 and allows the authors’ TF32/high matmul policy; native FP32 uses pedantic FP32. These are different numerical recipes with matched architecture and losses. The FP32 row is a separate precision control.

The follow-up reduces BatchNorm backward channel coefficients once before coalesced gradient application, and groups each learning phase’s gradient clears into one native launch. The prior categorical and FP16 weight-shadow fusions remain in both native versions. Scheduled parameter projections and target EMA still run after attempted updates, including AMP skips. These timings compare the combined follow-up rather than isolating each change’s causal contribution.

Setup includes native/learner construction, common-weight loading and its CPU readback audit, replay ingestion and preparation; it excludes block warmups. First and total warmups expose observed compilation/preparation costs. Separate action timings include the public action API and a CPU NumPy copy on every call. Checkpoint writing, replay audits and profiler traces are outside update bars. Reference-only author construction is outside the old-native setup value; full command wall times below include it, plus imports, fixture work and all rows in that process, but exclude environment installation.
